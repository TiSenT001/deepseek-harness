## A. 交互修复

### A1. 右键子菜单小三角布局（需求 1）

**现状**：`menu.tsx:179` 只渲染 `<span class="ov-menu-caret">▸</span>`；上一轮只改了面板宽度（210/180），小三角仍按 inline 流排在文字后，长标签会把三角顶到换行；子菜单展开方向也只按空间算 x/y，不与父项基线对齐。

**方案**
- 菜单项改为三列网格：`图标 | 标签(flex:1, 省略号) | 三角(固定 12px)`，三角永远贴右边缘且垂直居中。
- 子菜单展开时 y 对齐父项上边缘（首个可见项），超屏向上下翻转；x 与父面板留 2px 重叠区（鼠标斜移不断链）。
- 收纳后（见 F2）层级变浅，三角只在真正有子项时出现。

**验收**：截图对比：14 项菜单三角列右对齐；「移动到…」子菜单不再出现横向错位；窄屏 900px 下无换行。

### A2. 新建链接打开 = 浏览器新标签（需求 3）

**现状**：`host.ts` 的 `openLink` 对 `http(s)` 已经 `window.open(target,'_blank','noopener')`；但 note-link 卡片创建走的是「添加笔记链接」，URL 卡片走 `insertUrlInput`，`打开` 对 URL 目标可能走了 `openPath` 分支。

**方案**：区分三类目标——`http(s)` → `window.open`；`pur-asset:` → 应用内预览；库内路径 → 工作区。补一条 URL 卡片的端到端用例，确保「打开 / 新标签页 / 右侧」对 URL 都只做新标签（右侧打开对 URL 退化为新标签）。

**验收**：新建一个 URL 卡片，点三种打开方式都只新增浏览器标签，不产生工作区标签/分栏。

### A3. 选中图片后按 F 应聚焦该图（需求 5）

**现状**：`controller.ts:203` 的 `f` 直接调 `fitToView`，而 `fitToView` **已经**按 `selectedIds` 取目标（`controller-view.ts`）。空白处正确、选中后不正确，说明问题在**按键到达 controller 之前**：焦点在画布外的元素（如刚右键关掉菜单后 body 失焦），或选区在 pointerDown 被清空。

**方案**：先复现（选中卡片→按 F→记录 `selectedIds.size` 与 `view`），按结果二选一：
- 焦点问题 → 面板挂全局 keydown（已有），补齐 `tabIndex`/`focus()` 恢复；
- 选区问题 → 修 pointer/keydown 的清理时机；
- 两者都不是 → 加「选中时以选区为 fit 目标」的显式单测锁死行为。

**验收**：单测 + Playwright：选中一张 300×200 图（画布 1440×900）按 F，图片占视口 ≥60% 且中心与视口中心偏差 <2px。

### A4. 拖入 .md 生成的卡片可点击进入（需求 6）

**现状**：拖入 `.md` 生成 `note-link` 卡片；双击走 `doubleClick` → 打开**编辑器**而不是导航。

**方案**：note-link 卡片单击选中、**双击打开链接**（与 Obsidian 一致），编辑改由右键「编辑」或 Enter；`doubleClick` 对 `note-link` 且 `link` 非空时执行 open 而非 edit。URL 卡片同规则。

**验收**：拖入 `笔记.md` → 双击卡片 → 当前标签跳到该笔记；URL 卡片双击 → 新标签打开。

## B. 系统集成

### B1. 用系统软件打开图片（需求 2）

**要设计的原因**：DSH 是 Web 前端，浏览器**不能**直接调起本地程序；但本插件有宿主侧（Node 权限），可以提供受控的「用外部程序打开」。

**方案（宿主能力 + 右键子菜单）**
1. 宿主路由 `POST /obsidian/api/system/open-file`：`{ path, program? }`，仅接受库内真实文件；`program` 缺省时用系统默认关联程序（Windows：`rundll32 url.dll,FileProtocolHandler <abs>`；macOS：`open`；Linux：`xdg-open`）。
2. 右键子菜单「打开方式 ▸」提供三项：
   - 用系统默认程序打开
   - 用其他程序打开…（Windows 走 `OpenAs_RunDLL`，即系统「打开方式」对话框）
   - 已记住的程序列表（`PS / WPS / 画图 / 自定义`，存在插件 `.data/open-with.json`，可增删）
3. 安全：路径必须解析在库根内（复用 `VaultFiles` 的路径校验）；每次调起记一条 `notice`；不在菜单里暴露任意命令行。
4. 仅对**库内文件**有效；插件资产（`pur-asset:`）先导出到临时目录再打开（`.data/open-tmp/`）。

**验收**：右键一张库内 png → 用系统默认程序打开 → 系统看图器弹出；选「用其他程序打开…」→ 系统「打开方式」对话框。

### B2. 弹出独立窗口（需求 7）

**两条路线，建议先 A 后 B**

| 路线 | 做法 | 代价 | 适用 |
|---|---|---|---|
| **A（推荐先做）** | `window.open('/obsidian?popout=<path>')`，客户端识别 `popout` 后只渲染单画布（隐藏文件树/右栏/标签栏），窗口尺寸 1200×800 | 纯前端，立刻可用；浏览器窗口而非系统原生 | 双屏对照、参考图常驻 |
| B | 宿主侧 Electron `BrowserWindow`（仅 Desktop 端可用），Web 端退化为 A | 需 desktop 构建接线，Web 环境无 Electron | 需要「永远置顶/无边框」时 |

**方案 A 细节**：popout 页复用同一个 `PurStudioPane`，只挂最小外壳；与主窗口通过 `BroadcastChannel('pur-doc:<path>')` 同步保存事件（避免两边同时写）；关闭即释放。若同画布已在主窗口打开，popout 只读或提示「以副本打开」。

**验收**：右键「弹出为新窗口」→ 新窗口只显示画布；在其中拖动图片，主窗口刷新后看到结果；关闭窗口无报错。

## C. 视图与分栏

### C1. 右侧打开显示图片本体（需求 4）

**现状**：`openAsset` 走 `PurAssetPreview`（浮层，居中或右半），不是真正的分栏视图；用户要的是**右侧 pane 显示图片**。

**方案**：引入虚拟路径 `pur-asset:<id>` 作为可打开的「文档」。
- `VaultPage.openPath` 接受非库路径，直接开标签（不查索引）；
- `MainPane` 分派：`path.startsWith('pur-asset:')` → `PurAssetPane`（图片 + 适配窗口、缩放/拖动、Esc 关闭、标题=资产名）；
- 「右侧打开」= `openPath('pur-asset:<id>', 'right')`，走已有 split 逻辑（先开标签再分栏）；
- 浮层预览保留给「打开」的轻量场景（可配置：默认用 pane，Alt 用浮层）。

**验收**：右键图片 → 在右侧打开 → 右栏出现独立图片标签（不是画布），可缩放；关闭标签不影响画布。

## D. 编辑器统一

### D1. 一个编辑器引擎（需求 9、16）

**现状**：`PurTextEditor`、`PurNoteLinkEditor`、`PurLineEditor`、`PurGroupEditor` 四个组件各自实现外壳、按钮、焦点与提交逻辑；代码节点复用 `PurTextEditor`，视觉与文本卡片一致但字段不同。

**方案**：抽 `PurCardEditor`（一个外壳 + 字段槽）：
```
PurCardEditor
├─ 外壳：标题栏 / 关闭 / 提交(Enter+Ctrl) / Esc 取消 / 拖动条
├─ 字段槽（按 element.type 装配）
│   ├─ 正文：textarea（text/code 共用，code 用等宽，行号可选）
│   ├─ 链接：路径选择器（note-link）
│   ├─ 标签：单行（line）
│   └─ 名称：单行（group）
└─ 可选区：引脚编辑器（code-node）
```
- 统一间距 token：`--pur-editor-pad=12`、字段间距 8、按钮组右对齐、输入框行高 1.5；
- 提交语义统一：`Ctrl+Enter` 保存、`Enter` 换行（正文）/提交（单行）、`Esc` 取消并还原；
- 视觉：与画布卡片同圆角（8px）、同边框色，去掉各编辑器各自的内联样式。

**验收**：五种卡片（文本/代码/note-link/连线/分组）打开编辑器后，外壳尺寸、按钮位置、间距完全一致；截图对比。

### D2. 缩放与选中的 UI 迭代（需求 16）

- 选中框：8 个控制点（角点 + 边中点），角点等比（见 F1），边中点自由；
- 控制点 6px 视觉 + 10px 命中区，缩放到 30% 以下时只保留四角；
- 多选时统一包围框 + 虚线，拖拽整组；
- 缩放锚点：默认对角固定（拖右下角时左上不动）；
- 光标：角点 `nwse-resize`/`nesw-resize`，边 `ns-resize`/`ew-resize`。

**验收**：拖角点等比、拖边自由；低缩放下控制点不糊、不误触。

## E. 代码节点片段库（需求 10）

**目标**：写代码 + 引脚 → 存进「右键栏」→ 可增删，最终删掉库内 `代码/` 目录下的 md 文件。

**方案**
1. 数据：插件数据目录 `.data/code-nodes.json`（**不进知识库**），结构：
   ```json
   { "version": 1, "nodes": [ { "id": "…", "title": "…", "category": "…", "code": "…", "inputs": [...], "outputs": [...] } ] }
   ```
2. 右键菜单：`代码节点 ▸` → `内置预设 ▸`（现有 58 个）/ `我的片段 ▸`（用户库，悬停显示删除）/ `保存当前节点为片段`。
3. 保存：编辑器底部「保存为片段」按钮 → 取名 + 分类 → 写入 JSON（不需要库内文件）。
4. 迁移：知识库 `代码/*.md` 若存在，提供一次性「导入为片段」按钮（解析 fenced code + 引脚注释），导入后用户可自行删除文件。
5. 与生成代码流程（`gen-js`/`gen-py`）解耦：片段只是节点模板，不参与导出。

**验收**：新建代码节点 → 写代码 + 加 2 个引脚 → 保存为片段 → 右键栏出现 → 新画布可直接插入 → 删除片段后不再出现。

## F. 画布能力

### F1. 等比缩放（需求 13）

- 图片元素：四个角点**始终等比**（默认），按住 `Alt` 临时自由；边中点只改宽/高（图片会裁切显示，不拉伸）。
- 文本/代码/note-link 卡片：角点自由缩放，边中点自由；文本高度可「随内容自适应」开关。
- 序列化保留 `w/h`，等比只在交互层约束，不改数据格式。

**验收**：拖图片角点，宽高比误差 <0.5%；拖文本角点，宽高独立变化。

### F2. 右键栏收纳（需求 12）

**现状**：元素菜单 14 项，其中 7 项可折叠。**目标：顶层 ≤9 项**。

提议分组：

| 顶层 | 子菜单内容 |
|---|---|
| 打开 ▸ | 打开 / 在新标签页打开 / 在右侧打开 / 跳转到嵌入的笔记 |
| 关联 ▸ | 关联笔记 / 修改关联 / 取消关联 / 嵌入当前笔记 |
| 编辑 | 直接保留（最高频） |
| 图层 ▸ | 置于顶层 / 上移 / 下移 / 置于底层 |
| 排列 ▸ | 排列 / 顶对齐 / 左对齐 / 居中 / 水平等距 / 统一高度 / 统一宽度 |
| 引脚 ▸ | 添加输入 / 添加输出 / 删除输入 ▸ / 删除输出 ▸ |
| 代码节点 ▸ | 内置预设 / 我的片段 / 保存为片段 |
| 保存/导出 ▸ | 6 项（现有） |
| 复制 · 创建副本 · 删除 | 保留顶层（高频） |

**验收**：任意元素菜单顶层 ≤9；子菜单展开后三角对齐（见 A1）。

### F3. 左侧栏图标（需求 15）

**现状**：manifest 用默认方块图标，与「画布」语义无关。

**方案**：画布语义图标——一个画框 + 内部两个对齐矩形 + 一个定位点，单色描边 1.5px，24×24 内 20×20 安全区；同时出 16/24/32 三档。沿用 DSH 图标风格（无填充、圆角端点）。给出灰度与浅色主题对比图。

**验收**：左侧栏图标与「画布/画板」直觉匹配；16px 下仍可辨识。

## G. 性能与逆向（需求 8、14）

### G1. 已有结论（上一轮逆向）

- PureRef 2.1.1：Qt6 + **QGraphicsView 光栅渲染，无 OpenGL**（`opengl32`/`Qt6OpenGL`/`glTexImage` 均不存在）；
- 解码走 `QThreadPool`，位图缓存 `QPixmapCache`；坐标为 `BigRational`（精确分数，缩放不漂移）；
- `.pur` = Qt `QDataStream` 序列化，图片以 `[uint32 BE 长度][原始 JPEG 字节]` 内嵌；
- 我们已落地：内容寻址资产（`sha256[:16].ext`）+ `pur-asset:` 协议；实测 119MB / 261 图 → 文档 126KB、打开 98ms、堆 58MB、平移 p99 16.8ms。

### G2. 尚未拿到 / 待补

- 函数级结论（Ghidra 脚本因 OSGi 类加载失败未跑通）——需要换 Java 脚本或 headless 直接调用；
- 缩放分层策略（是否用 mipmap/多级位图）、视口外剔除的判定阈值、拖拽期重绘节流参数。

### G3. 性能设计（目标：单画布 1000 图不卡）

| 手段 | 说明 | 预期 |
|---|---|---|
| 视口剔除 | 只绘制与视口相交的元素（含 1 屏预取） | pan 时 CPU 降一个量级 |
| 缩略图金字塔 | 每个资产生成 256 / 1024 / 原图三级，按 `scale×显示尺寸` 选级 | 低缩放不读原图 |
| 解码 LRU | 上限按字节（默认 256MB）或张数，超出按最近使用释放位图 | 内存可控 |
| 拖拽降采样 | 拖动/缩放期间用缩略图绘制，松手后补原图 | 交互恒定 60fps |
| 批量加载 | 打开时只解码视口内图片，其余按需 | 首开 <300ms |

**验收**：构造 1000 图、总 800MB 的画布：打开 <800ms、pan p99 <16ms、内存峰值 <400MB；对比数据写进 ROADMAP。

## H. 架构（需求 11）

**原则**：先内核、后适配、最后 UI；任何新能力都先进 `pur-kernel`（纯函数/纯状态），客户端与 Obsidian 适配器只做 I/O 与渲染。

**拆分清单**
1. `pur-kernel/geometry`：包围盒、等比约束、缩放锚点（现有散落在 controller-*）。
2. `pur-kernel/history`：快照栈统一（现在 pushHistory/pushSnapshot 两套）。
3. `pur-kernel/serialize`：`.PurStudio` 读写已有，补 schema 版本迁移钩子。
4. `pur-kernel/capabilities`：宿主能力表（能否 popout / 系统打开 / 分栏），替代现在的零散布尔。
5. `client/pur/*` 里的 host 实现按能力拆文件，删掉重复的 `unsupported` 包装。

**验收**：`duplication` 检查无新增重复块；kernel 单测覆盖新增几何/历史逻辑；每个能力只有一处实现。

## I. 导入 PureRef `.pur` 画布（新增需求 18）

### I1. 实测到的两种容器（不是猜的）

用本机两个真实文件验证：

| 样本 | 大小 | 真实结构 |
|---|---|---|
| `test.pur` | 2.45 MB | **ZIP**：`PK\x03\x04`，内含 `contents.xml` + 3 个 jpg/png 条目 |
| `Work(1).pur` | 93.3 MB | **QDataStream**：开头是 `QString "1.10"`（格式版本），随后是元数据与图像块 |

`contents.xml`（ZIP 变体）内容极简：

```xml
<root>
  <image path="pinterest_884887026773080661.jpg" x="20" y="20" width="200" height="150"/>
  ...
</root>
```

QDataStream 变体（PureRef 原生）：头 4 字节是 QString 的**字节长度**（大端），随后 UTF-16BE 字符；图像以 `[uint32 BE 长度][PNG/JPEG 字节]` 内嵌（实测 224/504593/1410993 偏移处的长度前缀分别为 210/130/130，是缩略图；全文件另有 8 个 JPEG、28 个 PNG 签名）。

**修正上一轮的结论**：之前记录为「QDataStream + 原始 JPEG」不够准确——真实文件里既有 ZIP+XML 变体，也有 QDataStream + 长度前缀 PNG/JPEG 块的变体。

### I2. 分两阶段实现

**阶段 1：ZIP + XML（可立即做，可验证）**
1. 宿主侧新增 `POST /obsidian/api/pur/import-pur`：读文件 → 判定魔数（`PK` → ZIP；否则 QDataStream）→ 解出 `contents.xml` 与图像条目。
2. XML → 元素映射：`image` → 图片卡片（x/y/width/height 直接对应世界坐标）；未知标签（`note`/`label`/`group` 等）按需增量支持，未知项计数并在结果里报告。
3. 图像条目 → 复用 `storePurImage`（内容寻址，`pur-asset:<id>`），**不写入知识库**。
4. 插入画布：整体居中到当前视口，一次操作 + 一条历史快照，可一次 Ctrl+Z 撤销。
5. 入口：右键「导入 ▸ 导入 PureRef 画布（.pur / .purz）」，以及把 `.pur` 拖进画布。

**阶段 2：QDataStream 原生（需继续逆向）**
1. 先补逆向：修好 Ghidra 脚本加载（OSGi 类加载失败），定位场景反序列化函数，拿到 item 结构（位置/尺寸/旋转/透明度/层级/备注）。
2. 在拿到结构之前，先做**保守导入**：只抽取长度前缀合法的 PNG/JPEG 块，按原始顺序网格排布进画布，并明确提示「已导入 N 张图片，位置为近似排布」。
3. 拿到结构后替换为精确还原（位置、缩放、旋转、分组、便签文本）。

### I3. 验收

- 阶段 1：拿 `test.pur` 导入 → 3 张图按 (20,20)/(230,20)/(440,20)、200×150 精确还原；资产落 `.data/images`，知识库零新增文件。
- 阶段 2：`Work(1).pur` 导入不崩溃、不 OOM（93MB / 大图），图像数量与文件内签名一致；精确布局在逆向完成后用同一文件回归。

### I4. 风险

- 93MB 级别文件在宿主侧解压需要流式处理，避免一次性读入内存（Node 用 `zlib.inflateRaw` 流 + 分块读取）。
- PureRef 版本差异（格式版本 "1.10"）：解析器要按版本分支，并对未知版本给出「只导入图片」的降级提示。
- ZIP 条目名可能重名或含路径穿越（`../`），解压前必须做路径校验。
